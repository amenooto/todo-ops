# todo-ops

사내 AI 운영 파이프라인을 **실사용 시나리오로 검증하기 위한 무대**다. 실제 제품이 아니다.

- 이 레포는 `wellcho` 트래커의 이슈를 AI 에이전트가 받아 고치는 대상이다.
- 의도적으로 결함과 미완성 과제를 심어 두었다(아래 "심어 둔 과제").
- 에이전트가 만드는 브랜치는 `ai/<이슈키>` 규칙을 따른다.

## 실행

```bash
node src/server.js     # http://localhost:4000
npm test               # 내장 테스트 러너
```

의존성 없음 — Node 표준 라이브러리만 쓴다(설치 단계에서 막히지 않게).

## 구조

| 경로              | 무엇                              |
| ----------------- | --------------------------------- |
| `src/server.js`   | HTTP 서버 · 라우팅 · 정적 파일    |
| `src/store.js`    | 할 일 저장소(파일 영속)           |
| `public/index.html` | 화면                            |
| `public/app.js`   | 프런트 로직                       |
| `test/run.js`     | 테스트                            |

## 심어 둔 과제

에이전트가 풀어야 할 것들이다. 트래커 이슈로 등록해 두고 AI 에 배정한다.

1. 완료된 항목이 목록 맨 위에 남는다 — 정렬 규칙이 없다
2. 할 일 제목이 화면에 그대로 들어간다 — XSS
3. 저장소가 쓰기마다 전체 파일을 다시 쓴다 — 동시 요청에 유실 가능
4. 삭제에 확인 절차가 없다
5. 빈 제목도 등록된다 — 검증 없음
